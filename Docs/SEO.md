# Search and AI visibility

How HatePDF is built to be found — by Google and Bing, and by the assistants
(ChatGPT, Claude, Perplexity, Gemini) that now answer "how do I merge a PDF
without uploading it" directly. Everything here is enforced or generated by
the build; the manual steps are listed at the end.

## What the build guarantees

`npm run build` runs `scripts/audit-seo.mjs` over the finished HTML. It fails
the build when any page lacks a title, a 50–175 character description, a
canonical that matches the deployment origin, exactly one `<h1>`, a `lang`
attribute or an absolute share image; when an indexable page is missing from
the sitemap or a `noindex` page is in it; and when a live tool page or help
page ships without its `SoftwareApplication` and FAQ structured data.

Every live tool page renders `<ToolGuide slug="…" />` below the tool. That
component turns the tool's entry in `src/content/tools/*.md` into static HTML
(quick answer, steps, before-you-start, limits, FAQs, related tools) plus
`SoftwareApplication`, `HowTo`, `FAQPage` and `BreadcrumbList` schema. Adding
a tool means adding its content file, or the audit stops the build.

Generated at build time from the same config, so they cannot drift:

| Path | Purpose |
| --- | --- |
| `/sitemap-index.xml` | All indexable pages with real `lastmod` from git history; unfinished tools and endpoints excluded |
| `/robots.txt` | Allows every crawler, names the AI search/retrieval agents explicitly, points at the sitemap and `llms.txt` |
| `/llms.txt` | Markdown index of the site for language models and agents |
| `/llms-full.txt` | The complete help corpus in one Markdown file |
| `/og/<slug>.png` | Share image per tool |
| `CNAME`, `<indexnow-key>.txt` | Written only when the matching variable is set |

## Moving to hatepdf.com (or any domain)

The site derives every absolute URL from one variable. Nothing in `src/` names
the host.

1. Buy the domain. In the repository, **Settings → Pages → Custom domain**,
   enter `hatepdf.com` and enable *Enforce HTTPS* once the certificate issues.
2. At the registrar, add the four GitHub Pages `A` records for the apex and
   a `CNAME` for `www` → `bansi1701.github.io`.
3. **Settings → Secrets and variables → Actions → Variables**: add
   `SITE_ORIGIN = https://hatepdf.com`. Redeploy (push, or *Run workflow*).
   The build now emits `base: '/'`, canonicals on the new host, the CNAME
   file, and a sitemap and robots.txt at the root — where crawlers actually
   read them (on a `github.io` project site, `robots.txt` under `/ProjectPDF/`
   is never consulted).
4. The old `bansi1701.github.io/ProjectPDF` pages keep serving from the last
   deploy until the next one; GitHub cannot 301 them. Once the domain is live,
   register both properties in Search Console and use *Change of address*
   from the old property to the new one.

## Getting indexed and cited — the manual steps

1. **Google Search Console** — add `https://hatepdf.com` as a Domain property
   (DNS record) or URL-prefix property (HTML tag: paste the token into the
   `GOOGLE_SITE_VERIFICATION` variable and redeploy). Submit
   `sitemap-index.xml`. Request indexing for the homepage and five main tools.
2. **Bing Webmaster Tools** — import from Search Console, or verify with the
   meta tag via `BING_SITE_VERIFICATION`. Bing's index is what ChatGPT search
   reads; this step is not optional for AI visibility.
3. **IndexNow** — generate a key (`openssl rand -hex 16`), set `INDEXNOW_KEY`,
   redeploy. Every deploy then submits the sitemap's URLs to Bing, Yandex,
   Naver and Seznam within minutes.
4. **Brand mentions off-site** — assistants cite what other sites say about
   you as much as what you say. Cheap, honest places: the GitHub repository
   README, AlternativeTo and Product Hunt listings, a Hacker News *Show HN*,
   relevant Reddit answers (r/privacy, r/pdf, r/selfhosted) where the "no
   upload" property genuinely answers the question.
5. **Watch what gets cited** — in Search Console, filter Performance by query
   for `without uploading`, `offline`, `private`, `alternative`; in Bing
   Webmaster, check *Search performance → Copilot*. Perplexity and ChatGPT
   can simply be asked "what PDF tools don't upload my file?" monthly.

## Writing pages that rank and get quoted

- Lead with a one-sentence definition an assistant can lift verbatim
  (`helpQuickAnswer` produces this for tools). State numbers: "0 document
  bytes sent", the live tool count, retention windows.
- Procedural steps as numbered lists; questions as `<details>` FAQs. The
  2026 citation studies find longer, modular pages with definitions,
  numbers, comparisons and steps are what engines extract.
- One intent per page. The `IntentPage` component exists for a specific,
  distinct search intent (`split-pdf-without-uploading`). Near-duplicate
  landing pages for the same intent are doorway pages; do not add them.
- Comparisons name competitors only for facts they publish themselves,
  with links to the source. See `/alternatives/`.
- Titles under ~60 visible characters; descriptions 120–160 with the
  differentiator ("no upload, no account") when there is room. The audit
  allows a wider range so it flags mistakes, not style.
